# 市集調查：記錄玩家攤位與行情

2026-10-02。在成都市集實測逆向，原型為 `market_recorder.py`（CLI）。

## 記憶體結構

### 地圖上的擺攤玩家

其他玩家也是 `CCharObject`（vtable `0x5F5DC4`），只是 HP / 等級 / 座標欄位是預設值。

| 欄位 | 說明 |
|---|---|
| `obj+0x1E4` | 名稱（Big5） |
| `obj+0x138` | 動作狀態，`0x12` = 擺攤（其他：0x9 / 0xA / 0xD）。實測 27 擺攤 vs 55 非擺攤全分對 |
| `obj+0x3E4` | 攤位招牌（Big5），非擺攤為空 |

heap 中還有大量無名的空物件（`+0x138` 為 `0xCDCDCDCD`），以名稱非空過濾。

### 點開的攤位商品

商品只在點開攤位時跟伺服器要，寫進**自己的** `CCharObject`：

| 欄位 | 說明 |
|---|---|
| `self+0x3D0` | int32 商品數 |
| `self+0x3D4` | → item ptr[count] |

- 關掉視窗**不會清掉**，換一攤是同一塊陣列被覆寫：這是「最後看過的攤位」，不是「開著的攤位」。
- 其他玩家物件的 `+0x3D0` 是 `0xCDCDCDCD`；NPC 商店不會動到這裡。

商品實例：`+0x05` item_id、`+0x10` 數量（同背包）、**`+0x114` 單價**（遊戲內確認是單價）。`+0x118` 等於 `items.weight`，不是數量也不是耐久。強化 / 屬性 / 鑲嵌沿用 `read_equipment` 的 `ENHANCE_OFFSET` / `read_item_stats` / `read_item_inlays`（幻羽拂塵傷害 464–480 與遊戲一致）。

### 攤位視窗與攤主

- 視窗管理員（`reader._window_list`）的子視窗清單裡出現 `CWndShopList`（vtable `0x5FF524`）＝商店視窗開著；關掉就消失。**NPC 商店也用 `CWndShopList`**。
- 每個 CWnd*：`+0x0C` 自己的 handle、`+0x10` 父 handle。`CWndStatic`（vtable `0x5FEEDC`）的文字是 `[w+0x124]` 指向的 Big5 字串。
- **攤主名稱 = 與 `CWndShopList` 同一個父視窗底下的 `CWndStatic` 文字**，且該名稱是地圖上 `+0x138 == 0x12` 的玩家。NPC 商店的標籤對不到擺攤玩家，所以被排除。
- 頭頂名牌 / 招牌也是 `CWndStatic`（各自掛在別的父視窗下）。早期用「任何是攤主名字的標籤」或「開窗後新出現的標籤」判斷，會把走進畫面的玩家名牌誤認成攤主。

### 時序

- 新攤位：商品與攤主標籤在開窗後 0.15–0.75 s 內穩定。
- 重開同一攤：立刻讀到（緩衝區還是同一份），伺服器的新資料之後才可能覆寫 → 視窗開著時要持續讀。
- 換攤時可能讀到上一攤的舊資料：若內容與「上一次關窗時的內容」相同、且那份內容記錄給的是別的攤主，就等它變；超過 3 s 放棄。

## 價格判讀（使用者規則）

原始價格一律保存，類型是推導出來的：

| 規則 | 類型 | 統計 / 上傳 |
|---|---|---|
| 剛好 99,999,999 | 議價（飛鴿傳書談） | 不計入行情；預設不上傳 |
| 8 位數、開頭 ≥4 個 9、去掉開頭 9 後尾數 > 0 | 官幣價：尾數 = 百萬官幣（items 24086，值 1,000,000 銀兩） | 換算後計入 |
| 其他（含 88,888,888 這類重複數字） | 銀兩價 | 正常 |

**誘餌價**：有些攤主開極低的價格（例如 300），但讓自己身上的銀兩是滿的，所以實際上買不到，目的是吸引人來議價，招牌常寫「鴿」「談」。我們讀不到別人身上的錢，所以改用價格判斷：**單價（換算成銀兩）低於 `items.value` 的 1/10 就標為「疑似誘餌價」**。在 664 筆實測資料中，這條規則剛好抓到兩個招牌寫議價（「賣a可官X2 鴿~」「A價 飛鴿談」）的攤位，共 7 筆，正常的便宜貨（金創藥 140／基準價 250）沒有被誤抓。

玩家也可以手動把單筆上架或整個攤主標成「不採計」（`excluded_listings` / `excluded_sellers`）。誘餌價和不採計都保留原始資料，但不計入最低／中位／最高價，之後上傳時也預設不送。

## 資料模型（本機 `market.db`）

- `visits`：每次讀到一份穩定的攤位內容（攤主、招牌、地圖、時間、內容 JSON、指紋）。只留本機。
- `listings`：一筆上架 = `(攤主, item_id, 單價, 屬性指紋)`，`count` 為同款所有堆疊的數量加總，`first_seen` / `last_seen` / `ended_at`。重開同一攤只更新 `last_seen`；同款數量變少記為數量變化；不見了記 `ended_at`。
- 上傳（之後做）：只送 listings，key 不含時間，網站可跨使用者去重；伺服器由玩家上傳時選。

## 記錄時機

每個角色一個模式：`auto`（預設，在市集地圖 44 莫愁谷 / 172 藏海村 / 173 成都 / 174 洛陽才記錄）、`on`、`off`。

## 實作

- `reader.py`：攤位相關的記憶體讀取（擺攤玩家、商店視窗、攤主標籤、目前攤位商品）。
- `services/market_db.py`：`MarketDB`（schema、記錄差異、查詢、CSV）。
- `services/market_survey.py`：`classify_price`、`StallTracker`（開窗 → 等穩定 → 防舊資料 → 記錄的狀態機，純邏輯可測）、`MarketSurveyManager`（單一背景執行緒輪詢所有已定位角色）。
- worker 公開 `live_handle()`（`(pm, hp_addr)`），經 `CharSession` / `WorkerManager` 給 manager 用，同 `walk_sample` 的路徑。
- API：`/api/characters/{pid}/market/status`、`PUT .../market/mode`、`/api/market/items`、`/api/market/items/{item_id}/listings`、`/api/market/export.csv`。
- 前端：角色分頁「市集 · 攤位調查」、全域「市價 · 攤位行情」。上傳回報之後再做。
