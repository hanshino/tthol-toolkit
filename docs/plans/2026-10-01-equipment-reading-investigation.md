# 讀取角色裝備：調查紀錄

2026-10-01。在 tthol-data 追紙娃娃圖層順序時（`tthola.dat` 的拼裝程式，見 tthol-data `scripts/paper_doll_investigation.md`），發現地圖上的角色物件直接存著每個裝備欄的道具。用 Cheat Engine 在遊戲執行中實測過，讀得到。

這份只是調查紀錄，程式還沒寫。

## 結論

- 地圖上每個角色（自己、其他玩家）都有一個角色物件，**vtable 固定是 `0x5F5DC4`**（目前這版 `tthola.dat`）。
- 物件的 `+0x374..+0x39C` 是 11 個裝備欄指標，**指標指向的道具實例在 `+5` 是道具 ID**（int32，未對齊），可以直接對照 `tthol.sqlite` 的 `items.id`。
- 物件的 `+0x1E4` 是角色名稱（Big5，null 結尾），可以用來認出自己（tthol-memory 已經會從 HP 結構 −228 讀名稱）。
- 完全唯讀，跟現在的 HP 掃描一樣不需要靜態指標鏈：掃記憶體找 vtable 值 → 驗證名稱 → 讀裝備。

## 角色物件結構

| 位移 | 型別 | 內容 | 依據 |
|---|---|---|---|
| `+0x000` | u32 | vtable = `0x5F5DC4` | 實測兩個角色相同 |
| `+0x088` | char[] | 目前動作名稱（`Wait`、`prepare`、`run` …） | 實測；`0x419060` 用它查圖層順序 |
| `+0x1E4` | Big5 | 角色名稱 | 實測（赫斯提雅、牛肉炒麵） |
| `+0x1F1` 一帶 | Big5 | 疑似稱號 | 實測（不定時赫星星），未確認 |
| `+0x221` 一帶 | Big5 | 疑似家族名 | 實測（築夢林），未確認 |
| `+0x374..+0x39C` | ptr ×11 | 裝備欄，見下表 | 實測 + 反組譯 |

## 裝備欄

裝備封包處理程式 `0x485e7b` 一帶依裝備位元（`items.flag_equip`，定義在 tthol-data `index.js`）切換，把新的道具實例指標寫進對應欄位。

| 位移 | 裝備欄 | 實測道具 |
|---|---|---|
| `+0x374` | HEAD（推測） | 兩個角色都是空的，**未確認** |
| `+0x378` | CAP 帽 | 50441 天銀蒼龍盔 |
| `+0x37C` | BODY 衣 | 50442 白銀蒼龍甲 |
| `+0x380` | FOOT 鞋 | 50443 白銀蒼龍靴 |
| `+0x384` | WING 背飾 | 50379 鋼鐵柔心 |
| `+0x388` | HORSE 坐騎（bit 0x800） | 50588 終極大萌王 |
| `+0x38C` | ORNAMENT_1 左飾（bit 0x100） | 50482 魅影面具 |
| `+0x390` | ORNAMENT_2 中飾（bit 0x200） | 21706 漂浮聖誕襪 |
| `+0x394` | ORNAMENT_3 戒指（bit 0x400） | 22056 極品藍指環 |
| `+0x398` | 左手（HAND_L） | 20806 綠甲盾 |
| `+0x39C` | 右手 / 雙手（HAND_R / HANDS） | 55004 龍躍鳳鳴手套、20390 真龍短劍 |

- 空欄位是 0。
- 讀法：`ptr = read_u32(ent + off)`；`ptr != 0` 時 `item_id = read_i32(ptr + 5)`。
- 其他用途：`+0x388` 有值時，遊戲用騎乘版的圖層順序（紙娃娃那邊已驗證）。

## 實測方式

Cheat Engine（CE MCP bridge）在 `0x4190a4` 下只記錄的硬體中斷點。此處 `esi = [edi]` 就是角色物件，角色轉身或換動作時才會觸發。抓到兩個物件後，用 Lua 讀 `+0x374..+0x39C` 和 `[ptr+5]`，再到 `tthol.sqlite` 查名稱，類型與裝備欄全部吻合。

## 建議做法

1. 掃描可寫的私有記憶體區段，找 4-byte 對齊、值等於 vtable 的位置。
2. 驗證候選：`+0x1E4` 是可解碼的 Big5 名稱，`+0x088` 是已知動作字串。
3. 名稱等於 HP 結構 −228 的名稱 → 自己的角色。其他符合的都是畫面上的其他角色。
4. 讀 11 個裝備欄 → `items` 表查名稱 / 類型。

## 待解問題

1. **外裝欄（EXTRA_CAP / EXTRA_BODY / EXTRA_HORSE …，bit 0x100000 以上）不在這段欄位裡。** `0x485e7b` 把這些位元分到 `0x4861c2` 等別的分支，還沒追。
2. **vtable 位址會隨客戶端改版變動。** 不能寫死 `0x5F5DC4`，要改成用特徵碼從 `tthola.dat` 找出來，例如角色建構函式裡寫 vtable 的那條指令。
3. **`+0x374` 是不是 HEAD**：要找一個有裝頭部道具的角色確認。
4. **掃描速度**：預估一秒內，未實測。
5. 名稱以外的字串（`+0x1F1`、`+0x221`）是什麼欄位，未確認。
