> 狀態：**草稿，等使用者看過**（2026-10-08，分支 `feat/lingxiao-dungeon`）。還沒寫程式。
> 第一個要做的是凌霄閣；玄謎窟用來確認劇本格式套得進去；謎霧之森（私人副本）之後參考 genbu 的攻略 `content/guides/dungeon-mistforest.mdx` 來做。

## 目標

以後新增一個副本，主要工作是寫一份劇本，不用重寫走路、打怪、過傳點、組隊這些共用的部分。

## 關鍵發現：「區域」可以從 DB 自動算出來

`map_walkability` 的可走格子，用八方向連通切成幾塊，每一塊就是一個「區域」，也就是傳點之間互不相通的房間或大廳。再把 `map_placements` 的怪群、傳點、落點分到各區域，凌霄閣的結果跟我手動分析的完全一致：

| 區域 | 有的怪群 | 落點 | 傳點 |
|---|---|---|---|
| 大廳 | G11 弒殺狂偶、G12 綠毒殭屍 | 1、2 | 257（往天梯） |
| 紫微垣 | G13、G14、G15 詛咒將軍 | 3、4、104、106、108 | 259（往天梯）、263、265、267（三間房） |
| 天樞之間 | G16 紫毒殭屍 | 103 | 264（回紫微垣） |
| …… | | | |
| 天市垣 | G32、G36 青面妖鬼 | 7、118–124 | 20（最後出口） |

所以引擎只要看「角色站在哪一格」，就知道自己在哪個區域、這一區有哪些怪群、哪些傳點。中途加入時，用這個判斷該從劇本哪一段接著做。

每個傳點的開啟條件（C37 群組存活數、C52 地圖變數）、目的地和落點，也都能從 `map_event_ops` 讀出來。引擎過傳點時就知道「要先清掉哪些怪群」。如果要清的怪群在別的區域，引擎會報告「這個出口要靠另一邊」，不會傻等。

## 三層架構

1. **引擎（共用）**：讀 DB 的區域、傳點、怪群；提供下面的基本動作；用位置判斷進度。戰鬥用 `Fighter`（`services/combat.py`），選怪沿用打怪模組的規則，限定在要清的怪群。
2. **團隊（共用）**：組隊（hook 已有 `party` / `invite` / `accept` / `leave`）、集合點、角色分工。
3. **劇本（每個副本一份）**：每個區域要做什麼、往哪個傳點走，以及 DB 說不清楚的東西。

### 引擎的基本動作

| 動作 | 意思 | 凌霄 | 玄謎 | 謎霧 |
|---|---|---|---|---|
| `Clear(群組…)` | 清光這幾群；看不到就照出怪點巡一圈（玄天塔的 sweep） | ✓ | ✓（水晶也是怪群） | ✓ |
| `Enter(傳點)` | 走上傳點，確認位置換到落點所在的區域 | ✓ | ✓ | ✓ |
| `FirstOpen(傳點…)` | 依序試，第一個能傳的就進去；都不能傳就往下做 | 紫微垣三間房 | | |
| `Hold(打 群組, 直到 群組 死)` | 守著打自然重生的怪，直到某隻出現並被打倒 | 天市垣等青面妖鬼 | | |
| `Talk(NPC, 選項)` | 走到 NPC 旁邊對話，用 jump id 挑選項（玄天塔已有） | 接任務、回報 | 接任務、回報 | 換圖 |
| `Recall()` | 用回城捲軸，回到入口再進場 | | 繞到另一間房 | |
| `Gather(限時)` | 團隊集合點：在傳點旁等全團到齊，一起踩 | 樓層出口 | | 5 人 |
| `Split(角色→步驟)` | 團隊分工：每個角色各做各的，最後在 `Gather` 會合 | | 成對房間各派一人 | 分頭踩機關 |
| `HasItem` / `PutItem` | 確認身上有道具；踩到機關點時遊戲自動收走 | | 三色寶箱換特殊窟 | 靈泉之水、避毒珠 |

### 劇本格式（Python 資料，放在 repo）

```python
Dungeon(
    key="lingxiao", name="凌霄閣",
    cooldown=Cooldown(hours=4),              # 記憶體讀不到任務計時，工具自己記
    entry=[...],                              # 從入口地圖開始的步驟
    areas={                                   # 區域用「落點 tag」或「怪群」指認，引擎換算成連通塊
        "大廳": Area(stage=42, landing=1, steps=[Clear(11, 12), Enter(257)]),
        ...
    },
    finish=[...],                             # 出副本之後（回報、領獎）
)
```

- 區域的鍵只是給人看的名稱；引擎用 `landing` 或怪群找到 DB 的連通塊。
- 步驟要能**重複執行**，但「看不到某群怪」不代表那群怪死了：水晶、房間怪、王都是事件生出來的，可能根本還沒生。所以一個區域算不算完成，**看出口的 `Enter` 有沒有成功**，不看怪群。`Clear` 只負責清掉看得到或巡得到的怪。這樣中途加入或斷線重來，從頭再跑一次該區的步驟也沒問題。
- 單元測試會拿每份劇本去比對 DB：引用的怪群、傳點、落點都要存在，`Enter` 的落點要真的落在劇本寫的下一個區域。劇本寫錯了，測試就會抓到。

```text
天市垣        Hold(打 32, 直到 36 青面妖鬼 死) → Gather(3 分) → Enter(20) → 入口 #100（落點 2）

  Talk(調查使者 7189, 要 6655)           回報，拿寶箱 31019 和經驗
```

**天市垣出口時限**：NPC 訊息說開 10 分鐘，但 DB 裡青面妖鬼的死亡事件是 3 分鐘後（delay 1800）重生 G32。會延長到 10 分鐘的是寶箱事件 32–36；你說三層沒有寶箱，而且那些事件會把出口需要的變數 305 歸零，看起來根本不會觸發。所以先當 3 分鐘，待實測。

**計時何時開始（影響組隊設計，待實測）**：照 DB，「3 分鐘後王重生、出口關閉」這個動作寫在**踩出口傳點**的事件裡（例如 259 的動作是「傳送＋延遲 1800 生成 G15」），不是寫在清完怪的時候。如果這樣理解沒錯，清完之後到有人踩出口之前，出口一直開著，倒數要等第一個人踩過去才開始。那麼我們自己的團隊沒有時間壓力：低等角色慢慢走過來就好，只有其他玩家先踩了才會開始倒數。實測方法：清完紫微垣後等超過 3 分鐘不要踩，看詛咒將軍會不會重生。

紫微垣和太微垣能用 `FirstOpen`，是因為房間傳點的條件本身就寫好了順序（例如 265 要「G16 死光且 G17 還活著」）。所以「試第一個能傳的」自然就照順序走；別人已經清過的房間，傳點不會開，直接跳過。

## 劇本草稿二：玄謎窟（左路線）

DB 的結構：起點（G201 忍者 ×33）有四個傳點，分別通往四間房，兩兩成對：右半邊是 A 豪豬房和 B 護法房，左半邊是 C 惡虎房和 D 眼鏡蛇房。**每間房的出口，要「另一間」的怪和水晶都清掉才會開**。右半邊兩間通往蜘蛛房（落點 106），左半邊兩間通往道士房（落點 107）。蜘蛛房和道士房同樣互相綁定，兩間都通往中忍大廳（落點 108）。大廳有三顆大水晶，分別開三條路線；左邊那顆 G233 的出口 288 直接通往盡頭 #317 的赤寶箱區。

重生時間：打破水晶後，成對房間的怪約 1 分鐘重生（delay 600，訊息也寫一分鐘）；蜘蛛房、道士房是 delay 900（訊息寫 30 秒，兩者對不起來，只能當大概）。

起點的提示（訊息 6600）寫的是「清除這裡的所有怪物才能和隊友前進到下一層，但**必須分四路進行闖關**」：照設計是四個人，一人一間房。

**四人版**（照設計的走法，也是用來驗證劇本格式的版本：用 `Split` 分工、`Gather` 會合）：

```text

  Talk(玄謎窟調查 7192 @ (84,38), 要 6668)   各自接每日任務 18909
  Enter(213:266)                             等級 ≥ 85、冷卻 20229 要過了 → 起點（落點 1）
起點          Clear(201) → Gather
              Split:
                甲 → Enter(256) A 豪豬房：Clear(202, 203 水晶) → Gather(右半) → Enter(265)  → 蜘蛛房
                乙 → Enter(257) B 護法房：Clear(204, 205 水晶) → Gather(右半) → Enter(264)  → 蜘蛛房
                丙 → Enter(258) C 惡虎房：Clear(206, 207 水晶) → Gather(左半) → Enter(271)… → 道士房
                丁 → Enter(259) D 眼鏡蛇房：Clear(208, 209 水晶) → Gather(左半) → Enter(272)… → 道士房
蜘蛛房（甲乙）Clear(210, 211 大水晶) → Gather(全團) → Enter(281)   → 中忍大廳（落點 108）
道士房（丙丁）Clear(212, 213 大水晶) → Gather(全團) → Enter(278)   → 中忍大廳

#317 赤區     Clear(217, 218) → Enter(3)               拿赤寶箱 24200，傳回無名村

  Talk(玄謎窟調查 7192, 要 6670)              回報，拿寶箱 31022 和經驗
```

（「271…」：C 房的出口是 272、D 房的出口是 271，各自要另一間清好才開。劇本裡寫成「每人踩自己房間的出口」，傳點編號由引擎從所在區域查出來。）

人數不到四個時，就是由同一個人在回城後補做缺的那幾間。所以劇本的分工要寫成「這幾件事要有人做」，再由引擎依實際人數分配；人不夠時，同一個人排兩件事，中間插一次 `Recall()`。

**單人版（照你說的玩法，待實測）**：先清好某一間，回城，再從成對的另一間進去踩出口。依 DB，回城、重新進場、再清一次 33 隻忍者、走到另一間，都要在約 1 分鐘的重生時間內完成，看起來很趕。

**要你確認**：
1. 實際上通常幾個人打？一個人回城繞的話，大概來得及嗎？
2. 你說的「進右半邊房間通完、回城、再衝左半邊」，是不是指：右半邊兩間由一人輪流打完到蜘蛛房，再回城，從左半邊打到道士房，讓蜘蛛房和道士房的水晶都破掉？

## 謎霧之森（之後做）

劇本形式相同，差在開場：

- `entry` 是組隊後，隊長在曼陀羅城找葵對話開私人副本，隊員跟著傳進去。
- 區域之間主要靠 NPC 對話換圖（`Talk`），很多步驟是「踩機關、放道具」，而不是清怪。
- genbu 的攻略已經把每次換區整理成一個 `<DungeonStep>`（哪張圖、打哪些怪群、NPC 與機關位置），寫劇本時直接照著轉。

## 組隊（第二步才做）

- 每隻角色都跑同一份劇本，各自判斷自己在哪個區域。
- `Gather` 是唯一需要同步的點：先到出口的人在旁邊待命，還沒到的人繼續推進；全團到齊（或剩下的時間不夠）就一起踩。
- 「殿後」：最後一個踩傳點，在那之前負責打追上來的怪。
- 同步狀態放在 app 裡（同一台電腦的多個視窗），不經過遊戲。

## 分期

1. **引擎＋凌霄閣單人**：讀區域和傳點、上面那組動作、凌霄閣劇本、劇本驗證測試，放在「日常」裡跟玄天塔並排，記錄 4 小時冷卻。

## 還沒解的問題

- 凌霄閣的出口倒數，是清完就開始，還是有人踩了才開始（見上方）。這會決定組隊要不要趕時間。

- 記憶體讀不到任務進度和計時，冷卻只能由工具自己記；在遊戲裡手動打的那次工具不會知道。進場被擋時，要看提示訊息再更正。
- 只看得到畫面內的怪，所以「怪群死光了沒」要靠巡出怪點確認（沿用玄天塔的 sweep）。
- 凌霄閣天市垣的毒氣、迷香（G0）分布在整張圖，只要不打就好；會不會影響走路，要實測才知道。
